## 2026-05 第一阶段：核心功能建设

### UI 重构
- Hero 图片只在总览页显示，不出现在每个页面顶部
- 所有页面统一 `workspace-shell` / `workspace-card` / `workspace-header` 风格
- 清理所有表单预填充文字，改为 `placeholder`

### AI 产品经理（docsManager）
从目标仓库 `docs/` 读取计划文档，LLM 解析候选任务，写回进度：

- `POST /api/projects/:id/sync-docs`：读取 docs/*.md，Claude 解析结构化候选任务，按优先级导入任务板
- `POST /api/projects/:id/update-docs`：将 Hub 任务状态写回 `docs/阶段进度追踪.md`
- `POST /api/projects/:id/daily-scan`：串联 commit 同步 + sync-docs + update-docs
- 默认每轮导入上限 8 个（`DOC_TASK_IMPORT_LIMIT`），可 query 参数临时覆盖
- 解析快照缓存到 `store.docTasks[projectId]`，用于进度对照

### AI 混合分析（semanticLinker）
- `POST /api/ai/refresh-analysis` 触发 Claude 语义分析，结果缓存到 store
- 输出：`semanticLinks`（任务/阶段/commit 关联）、`riskAnalyses`（风险解释）、`healthAnalysis`（健康度修正 ±5）
- 规则负责召回候选和硬阻断，Claude 负责语义判断和置信度，P1 不可被 LLM 降级

### 任务细则生成（assignmentBrief）
- 认领任务时自动生成 AI 任务细则：目标、步骤、验收标准、Git 证据模板、沟通要点
- LLM 优先，失败时降级为规则模板
- brief 嵌入任务详情页展示

### 晚会闭环优化
- `generateEveningReport` 统一入口：规则引擎对账 + LLM 增强 + 快照持久化 + 企微推送
- `GET /api/reports/compare` 使用晚报快照（`eveningEntry.commits`），不实时查询 activities
- 会后总结支持推送企微，格式符合企微 Markdown（无表格）
- `buildPreMeetingWeComMsg` / `buildMeetingSummaryWeComMsg` 统一格式化

### 阶段目标对照清单
- `GET /api/stage/checklist` 返回阶段节点 × 任务/commit/review 证据的对照状态
- 状态：已完成 / 推进中 / 高风险 / 阻塞 / 待补证据
- 总览页展示阶段进度，路径图渲染成节点副本视图

### 真实仓库接入与数据迁移
- 默认项目从本地演示迁移到 `CUEAITECH/Cue.AI`
- GitHub API 同步优先于本地 git，无需服务器 clone 产品仓库
- `migrateStore()` 自动处理：旧 repo 别名归并、旧 demo review 剔除、旧 linkedRef 修正
- `authorMap` 将 GitHub 用户名映射到中文成员名

### GitHub 自动同步调度器
- 启动 15 秒后触发一次同步
- 默认每 10 分钟同步一次（`GITHUB_SYNC_INTERVAL_MINUTES`）
- 每轮最多拉取 20 条 commit（`GITHUB_SYNC_LIMIT`），对最新 5 条生成 AI Review（`GITHUB_SYNC_DIFF_LIMIT`）
- 17:45 自动生成晚会作战包并推送企微

## 当前技术约定

### LLM 调用
- 统一入口：`callClaude(systemPrompt, userPrompt)` → 文本或 `null`
- System prompt 固定（不含日期/用户输入），保持 prompt cache 有效
- 每个调用方必须处理 `null` 并降级

### 路由
- `server/index.js` 的 `handleApi` 是顺序 if-else 链，路由定义顺序即优先级
- 新增路由前确认没有同路径的重复定义

### 时区
- 所有日期操作用 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Shanghai' })`
- 不使用 `new Date().toISOString().slice(0, 10)`（UTC 会差一天）

### AI Review 级别
- 固定四级：`Pass` / `Warning` / `Block` / `Escalate`
- LLM 输出经 `normalizeLevel()` 规范化（含中文映射）
- 只有 Block / Escalate 需要人工介入，计入 `pendingReviews`
