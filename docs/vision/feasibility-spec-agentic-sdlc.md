# CUE Agentic SDLC 可行性规格说明书

**版本**: 1.0  
**日期**: 2026-06-03  
**状态**: 已确认  
**前提**: 全部采用开源成果 + 前沿算法 + 团队微调，不自研基础模型

---

## Executive Summary

以当前最优开源组合 + 团队微调，可实现愿景的**约 62%**。

剩余 38% 中：
- **15%** 是当前全球范围内无工具可解的硬上限（音视频感知）
- **23%** 是理论可做但超出小团队当前资源边界（真正的持续学习 / 全自动多端协作测试）

这 62% 已经是**市面上没有任何一个产品做到**的东西。

---

## 架构定义

系统由 **5 层 + 5 条回流边** 构成：

```
①  想法 → 澄清反问 → 标准 PRD
②  PRD → 里程碑 + 任务 schema（依赖/验收/业务视图）
③  任务 → 自动建 PR / branch
④  实时监控：commit 状态 / diff 风险 / 业务缺口 / PR 还差什么
⑤  Browser agent 像人一样测试 → 记录进系统

E1  commit/PR 完成 → 任务状态自动翻转
E2  测试结果 → "业务是否真实现"
E3  diff 风险 → 阻断 / 新建修复任务
E4  完成情况 → 实时调整阶段/里程碑
E5  交付 → 下一轮迭代起点
```

---

## 逐层可行性

### ① 想法 → 澄清反问 → 标准 PRD

| 项目 | 内容 |
|---|---|
| **最优开源方案** | GitHub Spec Kit + 自定义领域澄清 prompt |
| **可实现度** | **85%** |
| **能实现的** | 结构化 PRD 生成、标准模板、歧义识别、多轮对话澄清 |
| **实现不了的** | LLM 无法自主判断产品领域的行业潜规则（需人工喂领域知识） |
| **微调工作** | 领域感知的澄清 prompt；PRD schema 与 CUE task 数据结构对齐 |
| **工期** | 2-3 周 |

### ② PRD → 里程碑 + 任务 schema

| 项目 | 内容 |
|---|---|
| **最优开源方案** | Taskmaster（依赖/验收/递归展开）+ Backlog.md 任务格式 |
| **可实现度** | **78%** |
| **能实现的** | 任务依赖图、验收标准生成、复杂度评估、递归子任务 |
| **实现不了的** | 业务/技术双视图（所有开源工具无此设计，CUE 必须自建）；隐式依赖检测 |
| **微调工作** | 在 Taskmaster schema 上加 `businessNote` / `milestoneId` / `evidenceRefs` 字段 |
| **工期** | 3-4 周 |

### ③ 任务 → 自动建 PR

| 项目 | 内容 |
|---|---|
| **最优开源方案** | GitHub API（已有）+ 现有 PR 流 |
| **可实现度** | **90%** |
| **微调工作** | 几乎不需要，PR 流已跑通 |
| **工期** | 1 周 |

### ④ 实时监控（四个子功能）

**④-a commit/PR → 任务完成度（E1）**
- 方案：TraceLLM 语义匹配 + 显式 task ID 双保险
- 可实现度：**80%**（显式 ID 时 95%，纯语义匹配 70%）
- CUE 种子：`semanticLinker.commitTaskLinks` 已有，24 个实证
- 工期：2-3 周

**④-b diff 风险 → 阻断（E3）**
- 方案：现有 `reviewer.js` + `riskEngine`（182 条已工作）
- 可实现度：**83%**
- 工期：1-2 周（接线，不造轮子）

**④-c 业务缺口分析**
- 方案：APM Planner 读代码库 + LLM gap analysis
- 可实现度（无 E2）：**52%** / （有 E2）：**71%**
- 硬限制：静态分析判断"文件存在"，无法判断"功能能用"
- 工期：4-6 周

**④-d 每个 PR 还差什么**
- 方案：PR diff + acceptance criteria → LLM checklist 比对
- 可实现度：**72%**（依赖 ② 的验收质量）
- 工期：2-3 周

### ⑤ Browser Agent 像人一样测试（E2）

| 测试类型 | 可实现度 | 说明 |
|---|---|---|
| 导航 / 表单 / 点击 | 75-80% | 当前 Web Agent 接近生产可用 |
| 视觉 QA（布局/色系） | 65% | LLM 有视觉感知，主观判断需基准 |
| 实时音视频（TRTC） | **8-12%** | **硬上限**：无工具有音频感知 |
| 多端实时协作 | 15-20% | 多 agent 协同极度不稳定 |
| **对 CUE 产品综合** | **约 45-50%** | 核心功能是音视频，命中最低格 |

最优开源：Skyvern / browser-use / Stagehand  
成本：$0.5-3/次，3-10 分钟/流程  
工期：6-10 周

### ⑥ 持续学习 + 实时纠偏

**⑥-a 纠偏（E4）**
- 方案：Taskmaster `update` + closed-loop replanning
- 可实现度：**65%**（依赖 E1+E2 信号质量）
- 工期：5-8 周

**⑥-b 持续学习**
- 方案：in-context learning（向量记忆 outcome）+ 权重动态调整
- 可实现度：**28%**
- 硬限制：真正的模型自我改进需要大量标注数据和训练基础设施
- 工期：10-14 周，早期效果不明显

## 不可逾越的硬上限

1. **音视频质量测试**：无任何 browser agent 有音频感知。估计 2027 年前无开源解法。
2. **真正的持续学习**：小团队无数据量、算力、MLOps 基础设施。
3. **完全自主的业务缺口判断**：音视频/实时协作场景必须有人在回路（Human-in-the-loop）。

---

## 建议构建序列

```
Phase 1（止血 + 验证，8-10 周）
  → E1 闭合：commit → 任务状态自动
  → E3 闭合：diff 风险接回任务
  → ② 重做：新 task schema（加验收/依赖/业务视图）

Phase 2（闭环成形，12-16 周）
  → ① 澄清反问入口
  → ④-c 业务缺口静态版
  → ⑥-a 纠偏：替换全量重解析

Phase 3（护城河，16-24 周）
  → ⑤ E2 browser agent（非音视频先）
  → ⑥-b 持续学习 in-context 版

Phase 4（研究级，时间未定）
  → 音视频测试 — 等工具链成熟
```
